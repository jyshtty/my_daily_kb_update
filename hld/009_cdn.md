# CDN (Content Delivery Network)

## What It Is
A globally distributed network of **edge servers** that cache content close to users.

```
User (Mumbai) ──→ Edge (Mumbai)  ──hit──→ content returned in ~10 ms
                       │
                      miss
                       ↓
                 Origin server (Virginia) ~200 ms, then cached at the edge
```

## Why Use One

| Benefit | How |
|---|---|
| **Lower latency** | Content served from a nearby edge |
| **Less origin load** | Cache hits never reach your servers |
| **Higher availability** | Edges can serve cached content even if origin is slow |
| **Bandwidth savings** | Fewer bytes leave your data centre |
| **DDoS / security** | Absorbs traffic at the edge, WAF, TLS termination |

## What to Cache
| Good fit | Poor fit |
|---|---|
| Images, video, CSS, JS, fonts | Highly personalized responses |
| Static HTML, downloads | Writes (POST/PUT) |
| Public API responses (short TTL) | Data that must be real-time |
| Video segments (HLS/DASH) | Per-user private data (unless carefully keyed) |

## Push vs Pull CDN

| | Pull (origin pull) | Push |
|---|---|---|
| How content arrives | Edge fetches from origin on first miss | You upload content to the CDN in advance |
| First request | Slower (cache miss) | Fast |
| Management | Easy, automatic | You manage uploads and removals |
| Best for | Most sites, large catalogs | Small, rarely changing sets (big releases) |

## How Requests Reach the Nearest Edge
- **GeoDNS** — DNS answers with the closest edge IP
- **Anycast** — same IP advertised from many locations; routing picks the nearest

## Cache Control
Behaviour is driven by HTTP headers:

```
Cache-Control: public, max-age=86400          # cache 1 day
Cache-Control: private, no-store              # never cache at shared caches
Cache-Control: s-maxage=600, stale-while-revalidate=60
ETag / Last-Modified                          # conditional revalidation (304)
Vary: Accept-Encoding                         # cache key varies by header
```

## Invalidation Strategies

| Strategy | Notes |
|---|---|
| **TTL expiry** | Simple; stale until TTL ends |
| **Purge / invalidate by URL or tag** | Immediate but can be slow/limited and costs money |
| **Versioned URLs (cache busting)** | `app.3f9c1.js` — new file = new URL, no purge needed. **Best practice** for static assets |
| **Stale-while-revalidate** | Serve stale instantly, refresh in background |

> "There are only two hard things in computer science: cache invalidation and naming things." — versioned filenames sidestep the first one.

## Tiered Caching / Origin Shield
```
Edge (many) → Regional/shield cache (few) → Origin
```
Misses from many edges collapse into one request to origin, protecting it from thundering herds.

## Private Content
- **Signed URLs / signed cookies** with expiry for paid or private media
- Origin access control so the origin only accepts requests from the CDN

## Pitfalls

| Pitfall | Fix |
|---|---|
| Caching personalised pages by mistake | `Cache-Control: private`, correct `Vary`, don't cache `Set-Cookie` responses |
| Low cache hit ratio | Normalise query strings, tune cache key, longer TTL |
| Stale content after deploy | Versioned asset URLs |
| Origin overwhelmed on a cold cache | Origin shield, request coalescing, pre-warm |
| CDN as single dependency | Multi-CDN for critical sites |

## Interview Quick Answer
> A CDN caches content on edge servers near users, cutting latency and origin load. Use pull CDNs with sensible `Cache-Control` headers, versioned URLs for static assets, an origin shield to protect the origin, and signed URLs for private content. Track cache hit ratio as the key metric.

## Rule of Thumb
Cache static content aggressively with versioned filenames, cache dynamic content only when it is safe to share, and measure the hit ratio.
